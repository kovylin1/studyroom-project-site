### Ждёт мержа — PR #61

1. **`scraper/kompas-update.mjs`** — одна команда на агрегатор, от сайта источника
   до живого каталога. Это и есть «шаг 4», ради которого всё делалось.

   ```
   node scraper/kompas-update.mjs --agg=edvoy --apply
   node scraper/kompas-update.mjs --list
   ```

   Шаги: сбор → рабочая копия обновляется с живого каталога → цены и программы
   этого агрегатора в копию → доля изменений → перенос → гейт. Порядок и причины —
   в шапке скрипта. Без `--apply` не пишет ничего.

   Защиты: код возврата коллектора, свежая рабочая копия, фильтр «только карточки
   этого агрегатора», порог 5% каталога, правила гейта на каждой карточке, гейт
   целиком в конце, откат одной командой из отчёта.

   Проверено сухим прогоном на QAHE: свои карточки 6, изменились 6 (0,6%), гейт зелёный.

## Мелочи, которые сэкономят время

- Рабочее дерево владельца часто стоит на своей ветке (например,
  `feat/wa-when-no-price` — переделка стиля менеджера). Правки по парсерам делать
  в отдельном worktree, иначе конфликт с его терминалом. Создавать с
  `git -c core.longpaths=true worktree add`: без этого падает на длинных именах
  файлов в `sources/kompas/newcards/`.
- Прогоны Navitas сносило по памяти машины. Коллектор кэширует результат каждого
  домена в `sources/kompas/navitas/domains/`, поэтому повторный запуск продолжает
  с места остановки. Уровень и отбор названий пересчитываются при сборке из кэша —
  уточнение правила не требует заново выкачивать тысячу страниц.
