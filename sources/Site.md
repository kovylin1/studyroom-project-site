# Парсер заграничных универов + автогенерация лендингов

> Диалог-обсуждение архитектуры. StudyRoom, май 2026.
> Это зеркало `inbox/Site.md` — источник истины по архитектуре проекта.

## Задача

Настроить систему, которая:
1. Парсит данные универов с **партнёрских сайтов** (офиц.) и **сайтов-агрегаторов** — API нет, только скрейпинг
2. Приводит данные к **единому формату**
3. **Автоматически создаёт лендинги** на сайте StudyRoom
4. **1 раз в месяц актуализирует** информацию (цены, наличие программ, дедлайны)
5. Платформа для лендингов — обсуждаем (WordPress / Тильда / Astro / самописное)

---

## 1. Что такое Astro

Генератор сайтов. Берёт **данные (JSON) + шаблон → выдаёт обычные HTML-файлы**.

```
data/oxford.json  +  template.astro  →  /oxford/index.html
data/mit.json     +  template.astro  →  /mit/index.html
```

Без БД, без PHP, без сервера. Просто папка с готовыми HTML, которую можно положить куда угодно.
Аналоги: Next.js, Hugo, Eleventy.

**Минус:** редактировать может только тот, кто понимает в JSON/git.

## 2. Тильда и аналоги — почему не подходят

| | Тильда | Webflow | WordPress |
|---|---|---|---|
| Массовая генерация 100+ страниц через скрипт | ❌ слабый API | ⚠️ дорогой API | ⚠️ можно, но плагины |
| Стоимость на 100+ универов | $20+/мес, лимит 500 страниц | $30+/мес | хостинг + поддержка |
| Дифф «что изменил ИИ» для ревью | ❌ нет | ❌ нет | ❌ нет |
| Lock-in (можно ли уйти) | сильный | сильный | средний |
| SEO / скорость | средне | средне | медленно |

**Главная проблема Тильды:** её API — для импорта товаров в каталог, не для генерации сотен лендингов. И не видно, что именно ИИ поменял за месяц.

Тильда хороша для 5-10 ручных лендингов. Для нашей задачи — нет.

**Почему не WordPress:**
- Лишний слой: БД, плагины, редактор который никто не использует
- Медленный TTFB
- Сложнее программно создавать/обновлять страницы
- Удобен только если маркетологи редактируют руками — а у нас страницы делает ИИ

## 3. Самописный + редактируемый человеком — 3 уровня

### Уровень 1 — Astro + Decap CMS *(рекомендация)*

- Данные в JSON в git
- Поверх — UI-админка `/admin` (бесплатная Decap CMS, бывшая Netlify CMS)
- Менеджер видит форму «Оксфорд», правит «Цена: 25000 → 26000», жмёт Save
- Decap **коммитит сам в git** → сайт пересобирается за 30 сек

**Бесплатно. Без сервера. Без БД.**

### Уровень 2 — Payload CMS / Directus + Astro

- Реальная админка как в WP (роли, превью, версии)
- Своя БД (Postgres), API из коробки
- Нужен VPS (~$10/мес) или managed (~$15/мес)

Брать, если через полгода Decap станет тесен.

### Уровень 3 — полностью самописная админка

Next.js + Prisma + свои формы. Делать не надо — Payload это уже за нас сделал.

## 4. Vercel / Netlify / Cloudflare Pages — что это и зачем

Это **хостинг для статических сайтов**. Роль = «куда положить готовые HTML, чтобы они открывались по адресу studyroom.kz/oxford».

### Что делают автоматически

1. **Слушают git-репозиторий.** Сделал коммит → подхватили
2. **Запускают сборку.** Видят Astro → выполняют `npm run build` → получают папку с HTML
3. **Раздают результат миру** через CDN (300+ серверов по планете → быстро из любой страны)
4. **Дают HTTPS-сертификат** автоматически
5. **Подключают свой домен** (studyroom.kz) одной кнопкой

### Полный цикл

```
ИИ-скрейпер обновил data/oxford.json
        ↓
git commit + push в репозиторий
        ↓
Vercel/Cloudflare увидел push → запустил Astro build
        ↓
Получил готовый /oxford/index.html
        ↓
Раздал через CDN → studyroom.kz/oxford открывается
```

**Время от коммита до живого сайта: 30-60 секунд.** Без серверов, без деплой-скриптов, без DevOps.

### Чем отличаются

| | Vercel | Netlify | Cloudflare Pages |
|---|---|---|---|
| Бесплатный тариф | щедрый | щедрый | **самый щедрый** (безлимит трафика) |
| Скорость в РФ/СНГ | средне | средне | **быстрее всех** (CDN ближе) |
| Удобство | топ | топ | чуть хуже UI |
| Лучше всего для | Next.js | любого | масштаб + СНГ-аудитория |

**Для StudyRoom** (аудитория в СНГ, много страниц, бесплатно подольше) — **Cloudflare Pages**.

### Почему это вообще существует

Раньше: купи VPS → настрой nginx → настрой SSL → настрой деплой → когда упадёт — чини в 3 ночи.
Сейчас: подключил git → забыл. Платформа сама всё делает, бесплатно, никогда не падает.

## 5. Архитектура — стек целиком

### Сбор данных (раз в месяц по cron)

- **Playwright** (TypeScript) для JS-тяжёлых сайтов агрегаторов
- **Cheerio / got-scraping** для статики офиц. сайтов универов
- **Claude API (vision + HTML)** для извлечения в schema, когда вёрстка нестандартная — даём HTML/скриншот, получаем JSON по Zod-схеме
- **Firecrawl MCP** как fallback (он сам рендерит JS и отдаёт markdown)

### Нормализация — единая Zod-схема `University`

```ts
{
  slug, name, country, city,
  programs[],
  tuition{},
  deadlines{},
  requirements{},
  scholarships[],
  lastChecked,
  sourceUrl,
  sourceHash
}
```

Каждый универ = `data/universities/{slug}.json` в git.

### Лендинги — Astro

- Один шаблон `[slug].astro` → генерит N статических страниц из JSON
- SEO из коробки, < 100 KB, идеален для Google
- Деплой на Cloudflare Pages — бесплатно

### Месячный апдейт — GitHub Actions cron

1. Скрейпит → сравнивает с прошлым JSON
2. Если diff (цена, дедлайн, отмена программы) → создаёт PR
3. Менеджер ревьюит изменения в Decap UI
4. Apprve → merge → автодеплой
5. Опционально: Claude пишет changelog «что изменилось» в Telegram-бот StudyRoom

## 6. Итоговая картина

```
[Cron 1 раз в месяц]
        ↓
[Playwright + Claude] ← скрейпит сайты универов и агрегаторов
        ↓
data/oxford.json (обновлён)
        ↓
git PR ← менеджер видит "цена изменилась 25k → 26k", апрувит в Decap UI
        ↓
git push на main
        ↓
[Cloudflare Pages] ← собирает Astro, раздаёт миру
        ↓
studyroom.kz/oxford ← новая цена живая через 60 сек
```

Вся цепочка — **ноль рублей в месяц** (на старте) и **ноль серверов** в обслуживании.

---

## 7. Главный tradeoff

Astro + Decap **быстрее, дешевле, лучше для SEO, проще автоматизируется**, чем Тильда/WP. Но если завтра захочется чтобы маркетолог сам менял текст без PR-логики — придётся прикрутить Payload/Directus (это +1 сервер). Для текущей задачи (ИИ делает всё, человек только апрувит) — это лишнее.
