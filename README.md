# StudyRoom — парсер универов и автогенерация лендингов

Проект-«мозг» для StudyRoom: собирает данные о заграничных универах с партнёрских сайтов и агрегаторов, нормализует их в единую схему и автоматически выкатывает лендинги на `studyroom.kz/{slug}`. Раз в месяц всё актуализируется само.

Источник идеи и архитектурного разбора: `inbox/Site.md` (май 2026).

## Описание

Сейчас в этой папке — стартовая площадка проекта: дашборд, который показывает этапы плана из Site.md, единая схема `University` и снапшот выбранного стека. Это ещё не сам Astro-сайт и не скрейпер, а навигация по проекту, чтобы держать общую картину.

## Стек (план из Site.md)

- **Сбор:** Playwright (TS), Cheerio / got-scraping, Claude API (vision + HTML → JSON по Zod-схеме), Firecrawl MCP как fallback
- **Нормализация:** единая Zod-схема `University`, по файлу на универ — `data/universities/{slug}.json`
- **Лендинги:** Astro, один шаблон `[slug].astro` → N статических страниц
- **Хостинг:** Cloudflare Pages (бесплатно, CDN ближе к СНГ, безлимит трафика)
- **Админка:** Decap CMS, коммитит правки прямо в git
- **Cron:** GitHub Actions раз в месяц → diff → PR → ревью в Decap → merge → автодеплой
- **Опционально:** Claude пишет changelog «что изменилось» в Telegram-бот StudyRoom

## Возможности (этапы)

1. Дашборд проекта (текущий index.html) — статус по 7 шагам из Site.md
2. Единая Zod-схема `University` (см. `data/university-schema.js`)
3. MVP Playwright-скрейпера — 1 партнёрский универ + 1 агрегатор
4. Шаблон Astro-лендинга
5. Подключение Decap admin
6. Прогон на 2–3 универах и масштабирование
7. GitHub Actions cron на ежемесячный апдейт

## Главный tradeoff

Astro + Decap — быстрее, дешевле, лучше для SEO, проще автоматизируется, чем Тильда/WordPress. Если позже маркетологу понадобится править тексты без PR-логики — добавим Payload/Directus (+1 сервер). Пока ИИ делает всё, человек только апрувит — это лишнее.
