# КОМПАС — приведение каталога к партнёрским источникам

**Кодовое имя проекта: КОМПАС.** В переписке ссылаемся так: «КОМПАС, сессия N».
Смысл имени: компас задаёт каждому вузу направление на его истинный источник данных.

**Дата:** 2026-07-22
**Проект:** studyroom-project-site
**Статус:** план согласован с владельцем, 5 сессий
**Ветка:** feat/orel-photo-fidelity (или новая feat/kompas — решить на старте сессии 1)

## Зачем

Каталог (807 вузов) собран из разных источников вперемешку. Владелец хочет, чтобы каждый
вуз брал данные из своего **партнёрского** источника и чтобы каталог совпадал с ним. Источники —
это 10 агрегаторов и ~35 прямых партнёров из партнёрского документа
(Google Doc, у владельца; пароли в репозиторий НЕ кладём).

## Железные правила (решения владельца)

1. **Две категории источника у каждого вуза:**
   - **Прямой партнёр** → источник данных = **офсайт вуза**.
   - **Партнёр через агрегатор** → источник = **сайт агрегатора**.
2. **Кто партнёр у агрегатора:** если в документе дан явный список — только эти вузы;
   если стоит просто ссылка без списка — **все** вузы этого агрегатора.
3. **Агрегаторы дополняют друг друга, не режут.** Вуз, встречающийся у нескольких
   агрегаторов, — это **одна** карточка на сайте; программы объединяются (union), а не
   дублируются и не создают вторую карточку.
4. **Из каталога ничего не удаляем. Не фабрикуем.** Вузы вне партнёрского списка не
   стираем — выписываем владельцу на решение.
5. **Работаем на копии, живой каталог не трогаем**, пока не доведём до идеала.
   Бэкап-эталон: `backups/catalog_2026-07-22_pre-partner-rebuild/` (807 файлов, снят 2026-07-22).
6. **Всё локально, «до иголки».** Достоверность важнее скорости; часы работы приемлемы.

## Сессии

### Сессия 1 — Разметка и инвентаризация (без сети, дёшево)

**Цель:** превратить документ в структурированный реестр и разметить каталог, ничего не качая.

- Собрать `scraper/sources/partner-registry.json`: по каждому агрегатору — тип доступа,
  правило («все» / явный список), URL; отдельно 35 прямых партнёров.
- Сопоставить со слагами каталога: прямые партнёры + именные списки (IAPro 11, QA 4).
- Разметить каждый вуз каталога полем `partnerSource`:
  `{ type: "direct"|"aggregator"|"none", via: "<агрегатор>"|null }`.
  Разметка идёт на РАБОЧЕЙ копии, не в живой каталог (см. правило 5).
- **Выдать владельцу два списка:** (а) вузы каталога вне партнёрского списка — на решение;
  (б) партнёры из документа, которых нет в каталоге, — недостающие карточки.

**Итог:** реестр + отчёт покрытия. Сети нет, стоимость низкая.

### Сессия 2 — Открытые агрегаторы: свежий сбор

**Цель:** скачать сегодняшние данные с 5 открытых агрегаторов (Kaplan, CATS, QA,
Oxford International, Navitas).

- По каждому — коллектор, пишущий выгрузку единой формы (как edvoy-extract:
  programs[title/level/tuition/duration], scholarships, campuses, description).
- Проверить, для скольких размеченных партнёров данные реально нашлись.

**Итог:** свежие выгрузки 5 открытых агрегаторов + отчёт покрытия. Есть сеть, средняя стоимость.

### Сессия 3 — Закрытые агрегаторы

**Цель:** данные по Edvoy, StudyGroup, GEDU, IAPro, QS.

- Edvoy/StudyGroup/GEDU: взять существующие снимки; при наличии логина владельца —
  обновить через управляемый браузер (Playwright/Chrome), пароли остаются у владельца.
- IAPro + QS: только с владельцем — управляемый браузер по залогиненной сессии
  ЛИБО выгрузка от владельца. Для QS сначала получить список партнёров.

**Итог:** выгрузки закрытых 5. Стоимость зависит от способа входа.

### Сессия 4 — Замер расхождений (каталог vs назначенный источник)

**Цель:** для каждого партнёрского вуза сравнить карточку каталога с ЕГО источником
(агрегатор для aggregator-партнёров, офсайт для прямых).

- Поля: число программ, названия, tuition + валюта, стипендии, кампусы, описание.
- Учесть правило 3: у мультиагрегаторных вузов эталон = ОБЪЕДИНЕНИЕ источников.
- Формат кейса — как у СОРОКИ/БОБРа, роутинг в панель `/manager`.

**Итог:** таблица расхождений по вузам и полям + кейсы в панель.

### Сессия 5 — Доведение каталога до идеала

**Цель:** применить исправления на рабочей копии и заменить ими живой каталог.

- Заполнить пробелы и починить расхождения по правилам 1–4 (не фабрикуя, ничего не удаляя).
- Слить мультиагрегаторные вузы в одну карточку (union программ).
- `validate-catalog` 807/0, `npm run build` exit 0, визуальная выборка глазами.
- Только после проверки — переключить рабочую копию в живой каталог; бэкап остаётся точкой отката.

**Итог:** каталог, приведённый к партнёрским источникам.

## Уроки, которые действуют и здесь (оплачены срезами 2–3)

1. Сначала ЗАМЕРЬ, потом делай выводы. Посылки не проверять на глаз.
2. Брак и совпадение ловятся ГЛАЗАМИ по выборке, а не цифрой «найдено N».
3. Не доверяй отчёту собственного кода — перепроверяй замером.
4. Гипотезу проверяй, а не объявляй.
5. `--dry-run` не должен писать в дерево; частичный прогon не должен затирать общий файл.
