# КОМПАС — приведение каталога к партнёрским источникам

**Кодовое имя проекта: КОМПАС.** В переписке ссылаемся так: «КОМПАС, сессия N».
Смысл имени: компас задаёт каждому вузу направление на его истинный источник данных.

**Дата:** 2026-07-22
**Проект:** studyroom-project-site
**Статус:** план согласован с владельцем, 6 сессий (3.5 добавлена 2026-07-22 по решению владельца)
**Ветка:** feat/orel-photo-fidelity (или новая feat/kompas — решить на старте сессии 1)

---

## Зачем

Каталог (807 вузов) собран из разных источников вперемешку. Владелец хочет, чтобы каждый
вуз брал данные из своего **партнёрского** источника и чтобы каталог совпадал с ним. Источники —
это 10 агрегаторов и ~35 прямых партнёров из партнёрского документа
(Google Doc, у владельца; пароли в репозиторий НЕ кладём).

## Железные правила (решения владельца)

1. **Две категории источника у каждого вуза:**
   - **Прямой партнёр** → источник данных = **офсайт вуза**.
   - **Партнёр через агрегатор** → источник = **сайт агрегатора**.
2. **Кто партнёр у агрегатора:** если в документе дан явный список — только эти вузы;
   если стоит просто ссылка без списка — **все** вузы этого агрегатора.
3. **Агрегаторы дополняют друг друга, не режут.** Вуз, встречающийся у нескольких
   агрегаторов, — это **одна** карточка на сайте; программы объединяются (union), а не
   дублируются и не создают вторую карточку.
4. **Из каталога ничего не удаляем. Не фабрикуем.** Вузы вне партнёрского списка не
   стираем — выписываем владельцу на решение.
5. **Работаем на копии, живой каталог не трогаем**, пока не доведём до идеала.
   Бэкап-эталон: `backups/catalog_2026-07-22_pre-partner-rebuild/` (807 файлов, снят 2026-07-22).
6. **Всё локально, «до иголки».** Достоверность важнее скорости; часы работы приемлемы.

## Сессии

### Сессия 1 — Разметка и инвентаризация (без сети, дёшево)

**Цель:** превратить документ в структурированный реестр и разметить каталог, ничего не качая.

- Собрать `scraper/sources/partner-registry.json`: по каждому агрегатору — тип доступа,
  правило («все» / явный список), URL; отдельно 35 прямых партнёров.
- Сопоставить со слагами каталога: прямые партнёры + именные списки (IAPro 11, QA 4).
- Разметить каждый вуз каталога полем `partnerSource`:
  `{ type: "direct"|"aggregator"|"none", via: "<агрегатор>"|null }`.
  Разметка идёт на РАБОЧЕЙ копии, не в живой каталог (см. правило 5).
- **Выдать владельцу два списка:** (а) вузы каталога вне партнёрского списка — на решение;
  (б) партнёры из документа, которых нет в каталоге, — недостающие карточки.

**Итог:** реестр + отчёт покрытия. Сети нет, стоимость низкая.

### Сессия 2 — Открытые агрегаторы: свежий сбор

**Цель:** скачать сегодняшние данные с 5 открытых агрегаторов (Kaplan, CATS, QA,
Oxford International, Navitas).

- По каждому — коллектор, пишущий выгрузку единой формы (как edvoy-extract:
  programs[title/level/tuition/duration], scholarships, campuses, description).
- Проверить, для скольких размеченных партнёров данные реально нашлись.

**Итог:** свежие выгрузки 5 открытых агрегаторов + отчёт покрытия. Есть сеть, средняя стоимость.

### Сессия 3 — Закрытые агрегаторы

**Цель:** данные по Edvoy, StudyGroup, GEDU, IAPro, QS.

- Edvoy/StudyGroup/GEDU: взять существующие снимки; при наличии логина владельца —
  обновить через управляемый браузер (Playwright/Chrome), пароли остаются у владельца.
- IAPro + QS: только с владельцем — управляемый браузер по залогиненной сессии
  ЛИБО выгрузка от владельца. Для QS сначала получить список партнёров.

**Итог:** выгрузки закрытых 5. Стоимость зависит от способа входа.

### Сессия 3.5 — Прямые партнёры: сбор с офсайтов

**Добавлена 2026-07-22 по решению владельца.** Дыра исходного плана: у 35 прямых партнёров
источник — **собственный сайт вуза** (правило 1), но ни одна из пяти сессий на сбор с этих
сайтов назначена не была. Сессия 4 предлагала сверять карточку с источником, которого никто
не собирал. Без этой сессии треть партнёрского списка остаётся непроверенной.

**Что известно на входе (замерено 2026-07-22):**
- в реестре **35** прямых партнёров, в каталоге размечено `type: "direct"` — **32**;
- карточек нет у двух прямых партнёров: **AURAK** (American University of Ras Al Khaimah)
  и **Istanbul / Demiroğlu Bilim** — они в «списке Б» сессии 1;
- в репозитории лежат **757 файлов** `scraper/sources/official-extracts/`, из них файл есть
  у **30 из 32** размеченных; без файла — `university-of-european-management` и
  `woosong-university`.

**Порядок работы:**

1. **Сначала замерить, что в `official-extracts` вообще лежит.** Эти файлы собирались НЕ под
   КОМПАС и не по его правилам. Проверить по выборке глазами: есть ли программы, есть ли цены
   с валютой, какой давности `scrapedAt`, не пустышки ли. **Пока это не проверено, считать
   прямых партнёров покрытыми НЕЛЬЗЯ** — «файл есть» и «данные годные» это разные вещи.
2. По результату замера решить объём: добрать двоих недостающих или пересобрать всех 32.
3. Для тех, кого собираем заново, — коллектор по офсайту в единой форме
   (`programs[title/level/tuition/duration]`, стипендии, кампусы, описание), выгрузка
   в `sources/kompas/extracts/direct/<slug>.json`.
4. Офсайт резолвить через `lib/official-site.mjs` (SSOT резолва, заведён в срезе 2), НЕ через
   `sourceUrl` карточки: у 237 вузов там стоит `edge.edvoy.com`, то есть агрегатор, а не офсайт.
5. Два партнёра без карточек — выписать владельцу отдельно, карточки НЕ фабриковать.

**Осторожно, оплачено прошлыми срезами:** офсайт как источник картинок дал 6 брака из 7
(`og:image` главной — это последняя новость вуза), а признак «взято с офсайта» не защищает
от ИИ-стока. К ценам это относится в той же мере: с офсайта берём только то, что явно
подписано как стоимость обучения, и записываем аудиторию цены (`feeAudience`) — у британских
вузов рядом лежат home-цены, которые казахстанскому студенту не подходят.

**Итог:** выгрузки по прямым партнёрам + список тех, у кого офсайт цен не отдаёт.

### Сессия 4 — Замер расхождений (каталог vs назначенный источник)

**Цель:** для каждого партнёрского вуза сравнить карточку каталога с ЕГО источником
(агрегатор для aggregator-партнёров, офсайт для прямых).

- Поля: число программ, названия, tuition + валюта, стипендии, кампусы, описание.
- Учесть правило 3: у мультиагрегаторных вузов эталон = ОБЪЕДИНЕНИЕ источников.
- Формат кейса — как у СОРОКИ/БОБРа, роутинг в панель `/manager`.

**Итог:** таблица расхождений по вузам и полям + кейсы в панель.

### Сессия 5 — Доведение каталога до идеала

**Цель:** применить исправления на рабочей копии и заменить ими живой каталог.

- Заполнить пробелы и починить расхождения по правилам 1–4 (не фабрикуя, ничего не удаляя).
- Слить мультиагрегаторные вузы в одну карточку (union программ).
- `validate-catalog` 807/0, `npm run build` exit 0, визуальная выборка глазами.
- Только после проверки — переключить рабочую копию в живой каталог; бэкап остаётся точкой отката.

**Итог:** каталог, приведённый к партнёрским источникам.

### Сессия 6 — Работа над ошибками

**Добавлена 2026-07-22 по решению владельца.** Отдельный этап: не собирать новое, а
**подтянуть все накопившиеся косяки**. За сессии 1–3 их набралось столько, что вперемешку
со сбором они не закрываются — каждый раз находятся по ходу и откладываются.

Правило этапа: **сначала то, что видно посетителю сайта**, потом внутренние долги.

**А. Недостоверные данные в живом каталоге (видно посетителю).**
1. **Фабрикованные цены Navitas** — `seed-navitas-uk.mjs` раздаёт цены из литеральной таблицы
   `UK_FEE_BAND_BASE` одинаково всем вузам; у 10 британских вузов они стоят прямо сейчас.
   По Oxford International настоящие цены уже получены, сид-цены оттуда убрать тоже.
2. **Выдуманные программы QA** — `scrape-qahe-all.mjs` при пустом парсинге подставлял
   `fallbackPrograms()` (3 несуществующие программы), а `duration`/`intake` брал из таблицы
   `LEVEL_PATTERNS` по уровню, а не со страницы. Проверить, что протекло в каталог.
3. Где источник цены не даёт — **не выдумывать**: снимать значение и уводить в кейсы
   `/manager` как «уточняется» (механизм готов, применялся для `tuition_zero`).

**Б. Записи, которые не являются тем, чем притворяются.**
4. **27 карточек Collab** — это страницы меню и блога («Visa Application», «TOEFL Exam»,
   «Partner With Us», заголовки статей), а не вузы.
5. **EnglishPath** — в выгрузке вместо программ пункты меню («Our Courses»,
   «General English Courses»). Та же болезнь.
6. **Дубли каталога** — `tamucc` + `texas-aandm-corpus-christi-university-direct-entry`,
   `liu-brooklyn` + `long-island-university-brooklyn-direct-entry`,
   `manchester-met` + `mmu-international-college`, пять карточек SRH.
   Ничего не удалять без решения владельца (правило 4).

**В. Разобрать накопленные кейсы панели `/manager`.**
7. СОРОКА: 987 расхождений цен, 0 разобрано.
8. БОБР: 1529 кейсов по жилью.
9. ОРЁЛ: 1100 фото-кандидатов ждут просмотра владельцем.

**Г. Долги кода.**
10. `npm test` в scraper гоняет vitest, а 8 тестовых файлов написаны на `node:test` —
    vitest их не видит и репортит «No test suite found». Родным раннером проходят 53/53.
11. Поле `partnerSource` добавить в Zod-схему, иначе метка не доедет до сайта
    (Zod по умолчанию отбрасывает лишние ключи).
12. Проверить, что починки прошлых сессий держатся: честный `--dry-run` и «частичный прогон
    не затирает общий файл» — обе болезни встречались повторно у разных скриптов.

**Итог:** каталог без выдуманных данных и без записей-самозванцев, разобранные кейсы панели,
зелёные тесты обоими раннерами.

**Место в очереди.** По номеру этап идёт последним, но пункты А1–А3 — это **недостоверность
на живом сайте**, и ждать до конца им не обязательно: их можно закрыть раньше, как только
появятся настоящие цены Navitas. Остальное разумно делать после сессии 5, когда каталог уже
приведён к источникам и правки не придётся вносить дважды.

## Уроки, которые действуют и здесь (оплачены срезами 2–3)

1. Сначала ЗАМЕРЬ, потом делай выводы. Посылки не проверять на глаз.
2. Брак и совпадение ловятся ГЛАЗАМИ по выборке, а не цифрой «найдено N».
3. Не доверяй отчёту собственного кода — перепроверяй замером.
4. Гипотезу проверяй, а не объявляй.
5. `--dry-run` не должен писать в дерево; частичный прогon не должен затирать общий файл.
