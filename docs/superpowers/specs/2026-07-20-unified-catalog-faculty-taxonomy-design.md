# Единый каталог: срез 1 — канон-таксономия факультетов

**Дата:** 2026-07-20
**Проект:** studyroom-project-site
**Статус:** дизайн согласован с владельцем, готов к плану реализации

## Зонтичная цель

Сделать так, чтобы данные всех коллекторов (ПАУК — программы, БОБР — жильё/кампусы,
ОРЁЛ — фото, + official) собирались в единый канонический файл каталога на вуз
(`site/src/content/universities/<slug>.json`) с той же насыщенностью, что на сайте
агрегатора (эталон — Kaplan). «Единая база данных» = **единый канонический JSON-слой**
(не отдельный движок БД): один файл на вуз — источник правды, из него строится сайт.
Совпадает с текущим file-based пайплайном, $0 инфраструктуры, git-friendly.

Сейчас `merge-programs.mjs` сливает в каталог только **программы** (дедуп по `title+level`)
и fill-null цены. Жильё, кампусы, фото, стипендии, описания, требования в merge **не текут** —
у ~29 вузов они остались от легаси `cli.ts`. Обобщение merge на все домены — большая
многодоменная задача, поэтому режем на срезы.

## Декомпозиция (каждый срез — свой PR, verified РЕВИЗОРом/build)

| Срез | Содержание | Когда |
|---|---|---|
| **1. Факультеты** | Канон-таксономия факультетов применяется в merge ко всем вузам/источникам | **сейчас (эта спека)** |
| 2. Жильё/кампусы (БОБР) | merge несёт accommodation/campuses | отдельной спекой |

Каждый следующий срез проектируется отдельно (своя спека → план → реализация).

## Проблема (срез 1)

Поле `faculty` у программ засорено несогласованной таксономией. Пример Massey:
дублирующиеся корзины одной области (`Business & Management` 76 + `Business` 33;
`Health & Medicine` 16 + `Health Sciences` 12; `Science` 68 + `Natural Sciences` 8;
`Humanities & Languages` 13 + `Humanities` 6; `Fine Arts` 59 + `Arts & Design` 33),
плюс плейсхолдеры (`Прочее` 36, `Short Courses` 105 как «факультет», `(none)` 3).
Фильтр каталога по факультету ломается: студент выбирает область — часть программ,
размазанных по дублям, не находится.

## Решения владельца

1. Делаем по шагам, первый шаг — факультеты.
2. Канонический набор факультетов (ниже) принят.
3. `Short Courses` **оставляем** как отдельную категорию в фильтре факультетов
   (не прячем, не сливаем с академическими, не переносим в другое поле) —
   самостоятельный пункт фильтра.

## Канонический набор факультетов

Хранимые значения — на русском (сайт русскоязычный, i18n `/en` отменён; фильтр
user-facing русский). Карта синонимов конвертирует существующие английские/вариантные
значения в канон.

| Канон (русский) | Поглощает (синонимы, примеры) |
|---|---|
| Бизнес | Business, Business & Management, Management, Marketing, Finance, Accounting |
| Инженерия и IT | Engineering and Computer Science, Computing & IT, Engineering |
| Наука | Science, Natural Sciences, Sciences |
| Здоровье и медицина | Health, Health Sciences, Health & Medicine, Medicine, Nursing |
| Искусство и дизайн | Fine Arts, Arts & Design, Art, Design, Music, Media |
| Гуманитарные и языки | Humanities, Humanities & Languages, Languages |
| Социальные науки | Social Sciences, Communication, Journalism |
| Право | Law |
| Образование | Education |
| Подготовка (Foundation) | Foundation, Pathway, Pre-Master's, Foundation Certificate |
| **Short Courses** | Short Courses (отдельная категория, не академический факультет) |

`Прочее` и пустые: сначала инференс по ключевым словам тайтла → канон; если не
определяется — `null` (не выдумываем; программа без факультета, попадёт в «без категории»
фильтра, не в мусорную корзину).

## Архитектура среза 1

Три единицы, каждая с одной задачей:

### 1. `scraper/sources/faculty-taxonomy.json` — SSOT таксономии
```json
{
  "canonical": ["Бизнес", "Инженерия и IT", "Наука", "Здоровье и медицина",
    "Искусство и дизайн", "Гуманитарные и языки", "Социальные науки",
    "Право", "Образование", "Подготовка (Foundation)", "Short Courses"],
  "synonyms": {
    "business & management": "Бизнес",
    "management": "Бизнес",
    "natural sciences": "Наука",
    "fine arts": "Искусство и дизайн",
    "arts & design": "Искусство и дизайн",
    "health & medicine": "Здоровье и медицина",
    "health sciences": "Здоровье и медицина",
    "...": "..."
  },
  "titleKeywords": {
    "Бизнес": ["business", "management", "marketing", "account", "finance", "mba"],
    "Инженерия и IT": ["engineering", "computer", "software", "data", "it"],
    "...": ["..."]
  }
}
```

### 2. `canonicalizeFaculty(rawFaculty, title, taxonomy)` — чистая функция
Порядок: (a) точное/нормализованное совпадение по `synonyms` (lowercase, trim);
(b) если raw уже канон — вернуть как есть; (c) если raw пуст/`Прочее` — инференс по
`titleKeywords` (первое совпадение); (d) иначе `null`. Ничего не выдумывает.
Юнит-тестируется изолированно (вход raw+title → канон/`null`).

### 3. Интеграция в `merge-programs.mjs`
На этапе применения каждой программы: `program.faculty = canonicalizeFaculty(program.faculty, program.title, taxonomy)`.
Применяется ко ВСЕМ вузам и источникам, не только Kaplan. Существующее валидное
канон-значение не портится (идемпотентно: канон → тот же канон).

### 4. Разовый backfill по текущему каталогу
Скрипт (или флаг merge `--faculties-only`) прогоняет `canonicalizeFaculty` по всем
`site/src/content/universities/*.json`, схлопывает дубли, чистит `Прочее`/пустые.
Идемпотентен (повторный прогон ничего не меняет).

### 5. UI-фильтр
Фильтр факультетов на сайте берёт список из фактических значений каталога → после
backfill там ровно канон-набор (~11 пунктов, включая `Short Courses`). Проверить, что
компонент фильтра не хардкодит старые английские названия; при необходимости — обновить.

## Провенанс и безопасность

- Меняется только поле `faculty` у программ. Цены, уровни, дедлайны, названия — не трогаем.
- Zod-схема остаётся SSOT; если она ограничивает `faculty` enum'ом — обновить enum на канон-набор.
- РЕВИЗОР/СОРОКА без изменений (факультеты не в их скоупе).

## План проверки

1. Юнит-тест `canonicalizeFaculty`: 8–10 кейсов (синоним, канон-идемпотент, инференс,
   `null`-fallback, `Short Courses`).
2. Backfill dry-run на Massey → дубли схлопнуты, `Short Courses` сохранён, `Прочее` разобран.
3. Полный backfill → `git diff --stat` только по `faculty`-строкам.
4. `cd site && npm run build` → exit 0, все страницы.
5. Спот-чек фильтра факультетов: ~11 пунктов, без дублей, `Short Courses` присутствует.
6. Повторный прогон backfill → 0 изменений (идемпотентность).
