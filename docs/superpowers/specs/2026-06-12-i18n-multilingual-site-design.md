# StudyRoom — мультиязычный сайт (RU/EN/KK), Phase 1: UI + каркас

**Дата:** 2026-06-12
**Статус:** утверждён владельцем (дизайн)
**Проект:** studyroom-project-site (Astro 5 каталог + per-uni лэндинги)

## Цель

Сделать основной сайт и лэндинги вузов доступными на трёх языках — русском
(текущий), английском и казахском — с видимым переключателем языка. Phase 1
покрывает **инфраструктуру i18n и перевод всего интерфейса (UI chrome)**.
Перевод прозы вузов на казахский — Phase 2 (отдельный фоновый пайплайн).

## Решения (утверждены)

- **Языки:** `ru` (default, на `/`), `en` (`/en/`), `kk` (`/kk/`).
- **Роутинг:** встроенный Astro i18n, `prefixDefaultLocale: false` —
  русский без префикса, остальные с префиксом пути. SEO-дружелюбно, статика.
- **Объём Phase 1:** UI сейчас, контент вузов — позже.

## Архитектура

### 1. Конфигурация (`astro.config.mjs`)

Добавить блок `i18n`:

```js
i18n: {
  locales: ['ru', 'en', 'kk'],
  defaultLocale: 'ru',
  routing: { prefixDefaultLocale: false },
}
```

### 2. Каркас переводов

- **`src/i18n/ui.ts`** — словарь строк интерфейса:
  `const ui = { ru: {...}, en: {...}, kk: {...} }`, ключи плоские
  (`nav.catalog`, `hero.title`, `filters.country`, `card.from`,
  `landing.programs`, `landing.scholarships`, `compare.add`, `footer.legal`…).
  Ориентировочно 80–120 ключей. `ru` — источник истины; `en`/`kk` обязаны
  иметь те же ключи.
- **`src/i18n/utils.ts`** — хелперы:
  - `getLocaleFromUrl(url): Locale` — определяет язык по первому сегменту пути
    (`/en/...`→`en`, `/kk/...`→`kk`, иначе `ru`).
  - `useTranslations(locale): (key) => string` — возвращает `t(key)` с
    фоллбэком на `ru` при отсутствии ключа.
  - `localizeUrl(path, locale): string` — строит эквивалентный URL в другом
    языке (снимает текущий префикс, добавляет нужный). Для переключателя.
  - `getLocalePaths(): Locale[]` — `['en','kk']` для `getStaticPaths`
    префиксных роутов (без default).
  - Экспорт типа `Locale = 'ru' | 'en' | 'kk'` и `defaultLocale`.

### 3. Страницы — без дублирования кода

Astro в статике не клонирует роуты по локалям автоматически. Чтобы не
дублировать ~1545 строк лэндинга:

- **Вынести тело рендера** там, где сейчас инлайн-разметка с захардкоженным
  текстом, в общие компоненты, принимающие `(data, locale, t)`:
  - тело per-uni лэндинга `[slug].astro` → `components/LandingBody.astro`
    (или набор секционных компонентов, если так чище);
  - index/compare опираются на уже существующие `HeroV2`, `Filters`,
    `UniversityCardV2` — этим компонентам добавляется проп `locale`/`t`.
- **RU остаётся на корне:** `pages/index.astro`, `pages/[slug].astro`,
  `pages/compare.astro` — рендерят общие компоненты с `locale='ru'`.
- **Префиксные роуты:** `pages/[lang]/index.astro`, `pages/[lang]/[slug].astro`,
  `pages/[lang]/compare.astro`:
  - `getStaticPaths` по `lang ∈ {en, kk}` (для `[slug]` — произведение
    `lang × 808 slugs`);
  - определяют `locale` из `Astro.params.lang`, рендерят **те же** общие
    компоненты.
- **`manager.astro` НЕ локализуется** — внутренний CMS, `noindex`.

Итог по числу страниц: `(808 + 2) × 3 локали ≈ 2430` статических страниц
(приемлемо для Astro static).

### 4. Контент-фоллбэк (Phase 1)

Схема `description` уже двуязычна: `paragraphs`/`keyFacts` (EN) +
`paragraphsRu`/`keyFactsRu` (RU). Правила выбора прозы:

- `ru` → `paragraphsRu` (фоллбэк `paragraphs`)
- `en` → `paragraphs` (фоллбэк `paragraphsRu`)
- `kk` → `paragraphs` (EN-фоллбэк, до Phase 2)

Остальная проза (названия программ, тексты стипендий, проживание, кампусы)
рендерится как хранится (в основном EN); переводятся **подписи и заголовки
секций** вокруг неё. Казахская локаль использует EN-фоллбэк для непереведённой
прозы.

### 5. Переключатель языка и SEO

- **`components/LangSwitcher.astro`** в шапке (`Base.astro`): `RU · EN · KK`,
  каждая ссылка = `localizeUrl(Astro.url.pathname, locale)`, активная локаль
  подсвечена, `hreflang`/`lang` на ссылках.
- **`Base.astro`** получает проп `locale` (или вычисляет через
  `getLocaleFromUrl`) и проставляет:
  - `<html lang={locale}>`;
  - `og:locale` соответствующий локали (`ru_RU`/`en_US`/`kk_KZ`);
  - `<link rel="alternate" hreflang="ru|en|kk|x-default" href=…>` для всех
    локалей текущей страницы;
  - переведённые `title`/`description` по умолчанию.
- Sitemap-интеграция автоматически подхватит сгенерированные `/en/` и `/kk/`
  страницы (фильтр manager/admin сохраняется).

## Вне объёма (Phase 2 и далее)

- Перевод прозы вузов на казахский (`paragraphsKk`/`keyFactsKk`), а также
  стипендий/проживания/кампусов на RU/KK — **отдельный фоновый пайплайн**
  (quiet_mode, рабочий кодворд: **ТІЛ**). Требует расширения Zod-схемы
  (добавить `*Kk` поля) и bulk-перевода 808 файлов.
- Локализация `manager.astro`.
- Локализация служебных строк скрейпера/CMS.

## Тестирование

- `npm run build` проходит; в `dist/` присутствуют `/en/` и `/kk/` версии
  index, compare и выборочных лэндингов.
- Ручная проверка: переключатель ведёт на корректный эквивалент пути;
  активная локаль подсвечена; `<html lang>` и `hreflang` корректны на всех
  трёх версиях одной страницы.
- Отсутствие непереведённых ключей: `en`/`kk` словари покрывают все ключи `ru`
  (можно проверить простым скриптом-сверкой ключей).

## Риски / заметки

- **Дубликат-контент SEO:** пока KK-проза = EN-фоллбэк, страницы `/kk/`
  лэндингов близки к `/en/`. Митигируется `hreflang`; полностью снимается в
  Phase 2.
- **Объём рефактора:** главная стоимость Phase 1 — аккуратно вынести
  захардкоженный текст из `[slug].astro` (1545 строк) в общий компонент без
  регрессий рендера. Делать секциями, сверяя билд.
- **Параллельные сессии:** работать на отдельной feat-ветке, стейджить файлы
  поимённо (правило каталога), не `git add -A`.
