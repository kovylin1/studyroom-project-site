## Зонтичная цель

Единый канонический JSON на вуз с паритетом полей как на агрегаторе. Четыре среза:
факультеты (готов) → жильё/кампусы (готов) → **фото (эта спека)** →
стипендии/описания/требования.

### Достоверность: 61% ссылок ведут на чужие картинки

Уникальных изображений **по содержимому** (sha1 самих файлов) — **2854** на 7074 ссылки.
**4287 ссылок (61%)** ведут на изображение, которое показывается более чем у одного вуза.

| Домен | ссылок на общие картинки | помечено `imgKind: stock` |
|---|---|---|
| галерея | 1721 | **0** |
| кампусы | 1621 | 1484 |
| жильё | 945 | 825 |

**1978 общих фото не помечены никак, из них 1721 — галерея.** Галерея — самое видное
место карточки: из неё берётся картинка-шапка.

По вузам: у **235** ВСЯ галерея состоит из фото, встречающихся у других вузов;
у **301** — часть; полностью своя галерея у **270**.

Худшие случаи: одно изображение стоит в галерее у **64** вузов, другое — у **60**.
Физически оба лежат по пути `/photos/ac-badem-university/bobr-4.jpg`, то есть путь
выдаёт общий сток за фото конкретного вуза. Стоковая комната `_lib/room-11.jpg` — у 41 вуза.

### Почему метка среза 2 не сработала

`mark-stock-photos.mjs` определяет сток одним признаком —
`img.startsWith('/photos/_lib/')` — и обходит только `accommodation` и `campuses`.
Отсюда два слепых пятна:

1. **галерея не обходилась вообще** → 1721 общее фото без метки;
2. **сток, скопированный в папку вуза** под именем `bobr-N.jpg`, не ловится путём →
   137 карточек кампусов и 120 карточек жилья остались непомеченными, хотя их картинки
   общие.

Отчёт среза 2 «2309 карточек помечены stock» верен буквально, но покрывает 54% реального
объёма общих фото. Формулировка «стоковые фото помечены» — неверна.

### Провенанса нет

У элемента галереи ровно два поля: `img` и `caption`. Ни источника, ни лицензии, ни
автора, ни даты. Манифеста происхождения фото в репозитории нет (проверены
`scraper/sources/`, `sources/`, `site/public/api/`). Определить, откуда взялась картинка,
невозможно ни для одной из 2854.

Отдельно: **325 фото — внешние ссылки** на `upload.wikimedia.org` и три сайта вузов.
Wikimedia отдаёт их под CC BY-SA, что требует указания автора и лицензии; сейчас не
указано ничего.

### Оговорка о природе цифр

«Картинка используется у нескольких вузов» — это **признак подозрения, не доказанный
брак**. Общее фото Лондона у двух лондонских колледжей может быть уместным. Настоящий
процент брака определяется только просмотром выборки глазами (урок среза 2: 29% и 8%
брака были видны глазами и невидимы в цифре «найдено N»). Поэтому визуальная выборка —
обязательный шаг реализации, а не опция.

## Решения владельца

1. **Чужое фото исчезает только тогда, когда на его место встало настоящее.** Пустых
   галерей не допускаем; до замены непроверенное фото остаётся на сайте, но с честной
   подписью.
2. **Источник замены: офсайт вуза первым, Wikimedia добором.** Атрибуция (автор +
   лицензия) хранится у каждого фото — без неё Commons использовать нельзя.
3. **Чистка и пометка — во всех трёх доменах** (галерея, кампусы, жильё). **Поиск замены
   на этом срезе — галерея и кампусы.** Фото общежитий — следующим шагом, вместе с
   разбором 1529 кейсов БОБРа.
4. **Автомат при жёстких условиях + визуальная выборка перед массовым применением.**
   Сомнительное — кейсами в `/manager`, как у БОБРа. Полный автомат отвергнут.
5. **Цель — максимальное заполнение при сохранении качества.** Достижимый процент замены
   определяется пилотом (см. ниже), а не назначается заранее.

## Архитектура

Реестр фото + три скрипта с одной задачей каждый + превью для глаз. Схема повторяет
срез 2 (`bobr-audit` → `bobr-apply` → вкладка в `/manager`), которая себя оправдала:
скрипт поиска физически не имеет права писать в каталог.

### 1. `scraper/sources/photo-registry.json` — SSOT провенанса

Строится `orel-audit`, идемпотентен. По каждому изображению:

```json
{
  "sha1": "...",
  "dhash": "...",
  "path": "/photos/glasgow/1.jpg",
  "width": 1200, "height": 800, "bytes": 245113,
  "usedBy": [{ "slug": "glasgow", "domain": "gallery" }],
  "provenance": { "source": null, "license": null, "author": null, "fetchedAt": null }
}
```

Два отпечатка: `sha1` ловит побайтовые копии, `dhash` (перцептивный) — то же изображение
в другом размере или пережатии. Только sha1 недостаточно: часть дублей замаскирована
ресайзом (`resize-photos.mjs` в репозитории есть).

### 2. `scraper/lib/photo-fingerprint.mjs` — чистая функция

Вход — буфер изображения, выход — `{ sha1, dhash, width, height }`. Юнит-тестируется
изолированно: одинаковые файлы дают одинаковый `sha1`; ресайз того же изображения даёт
разный `sha1`, но близкий `dhash`; разные изображения — далёкий `dhash`.

### 3. `scraper/orel-audit.mjs` — замер и пометка

Читает каталог и диск, строит реестр, проставляет `imgKind` во **всех трёх доменах**,
включая галерею. Ничего не качает, не удаляет и не заменяет.

Классификация одного фото:

| `imgKind` | Условие |
|---|---|
| `verified` | есть провенанс: домен офсайта вуза или Wikimedia-страница, привязанная к вузу |
| `shared` | отпечаток совпадает с фото другого вуза, провенанса нет |
| `stock` | лежит в `/photos/_lib/` **или** отпечаток встречается у ≥5 вузов |
| `unknown` | своё по отпечатку, но происхождение неизвестно |

Порог `stock` в 5 вузов — рабочая гипотеза, подтверждается или правится на пилоте по
просмотренной выборке.

Выход: обновлённый каталог (только поля `img*`), реестр, отчёт
`sources/audit/orel-audit.json` со списком дыр — вузы, отсортированные по количеству
`verified`-фото.

### 4. `scraper/orel-hunt.mjs` — МОТЫЛЁК, поиск замен

По списку дыр, для галереи и кампусов:

1. **Офсайт** (адрес берётся из `lib/official-site.mjs`, SSOT среза 2; известен у 603 из
   807 вузов): `og:image` главной, затем страницы About / Campus / Gallery / Life.
2. **Wikimedia**: Wikidata `P18` (главное изображение) и Commons-категория, привязанные к
   сущности вуза — не поиск по названию. Тройная защита среза 2 переиспользуется:
   сущность должна быть учебным заведением (`P31`), label должен совпадать с названием.

Фильтр кандидата: не логотип/герб/карта/портрет/иконка (по имени, размеру и пропорциям),
короткая сторона ≥800px, отпечаток не совпадает ни с одним чужим фото в реестре.

**В каталог не пишет.** Кандидаты — в `sources/photo-candidates.json`, файлы — в
`site/public/photos/<slug>/hunt-N.jpg`, с провенансом (URL страницы, лицензия, автор, дата).

### 5. `scraper/orel-apply.mjs` — применение

Автозамена только при всех условиях сразу: кандидат с домена офсайта вуза, прошёл
фильтры, отпечаток уникален. Иначе — кейс в `/manager` (существующий формат БОБРа).

Замена строго 1:1: `verified`-кандидат встаёт на место `shared`/`stock`-фото, и только в
этот момент старое исчезает из карточки. Число фото у вуза не уменьшается никогда.
Из каталога ничего не удаляется — заменяется значение поля.

### 6. `scraper/orel-preview.mjs` — визуальный контроль

Статическая HTML-страница: сетка «вуз → его фото до и после», с пометками и источником.
Просматривается глазами до массового применения; ссылка отдаётся владельцу.
Существующий `bobr-preview.mjs` — образец.

### 7. Схема данных

Единый набор полей у элемента галереи, карточки кампуса и карточки жилья:

```
imgKind:      "verified" | "stock" | "shared" | "unknown"
imgSource:    URL страницы, откуда взято
imgLicense:   "CC BY-SA 4.0" | "official-site"
imgAuthor:    автор (обязателен для Wikimedia)
imgCheckedAt: ISO-дата
```

Zod-схема `site/src/schema/university.ts` расширяется; поля опциональные, чтобы не
уронить build на непроверенных карточках. UI: у фото с `imgKind ≠ verified` — подпись
«иллюстративное фото»; у Wikimedia — автор и лицензия (требование CC BY-SA).

### 8. Чистка мусора — отдельным коммитом

1432 сироты и 1194 побайтовые копии удаляются **только после** того, как реестр докажет
отсутствие ссылок. Отдельный коммит, легко откатываемый. Ожидаемая экономия 400–500 МБ
из 1491 МБ.

## Пилот: 30 вузов перед массовым прогоном

Обещать долю заменённых фото до замера нельзя — это повторило бы ошибку среза 2.
Первым шагом реализации `orel-hunt` гоняется на 30 вузах, отобранных не случайно:
10 крупных университетов с офсайтом, 10 мелких колледжей с офсайтом, 10 без офсайта.
Результат просматривается глазами и даёт:

- реальную долю вузов, где нашлось ≥1 пригодное фото;
- реальную долю брака автопоиска;
- проверку порога `stock` (5 вузов) на живых данных.

После пилота владельцу сообщается достижимая цифра покрытия, и он решает, достаточно ли
её или нужны дополнительные источники. **Массовый прогон — только после этого решения.**

Гарантируется без оговорок только пометка: 100% фото получают `imgKind` (сейчас у
галереи — 0%).

## Охват: все вузы, единообразно

Пометка и реестр применяются ко всем 807 вузам и всем трём доменам. Правило владельца
«не половинчато» соблюдается на уровне пометки безусловно; на уровне замены — в пределах
того, что нашли источники, а ненайденное остаётся видимым кейсом, а не тихой дырой.

## План проверки

1. Юнит-тесты `photo-fingerprint.mjs`: идентичность, ресайз, разные изображения.
2. Юнит-тесты классификатора `imgKind`: каждая из четырёх веток + граница порога.
3. `orel-audit` на 30 вузах → пометки совпадают с ручной проверкой выборки.
4. Полный `orel-audit` → 100% фото классифицированы, `git diff` затрагивает только поля `img*`.
5. Пилот `orel-hunt` на 30 вузах → **визуальный просмотр превью**, доля брака измерена.
6. `cd site && npm run build` → exit 0, 2428 страниц.
7. `node scraper/validate-catalog.mjs` → 807/0.
8. Повторный прогон `orel-audit` и `orel-apply` → ноль изменений (идемпотентность).
9. Сквозной тест: после любого `--dry-run` рабочее дерево чистое
   (`git status --porcelain site/` пусто) — закрывает открытый долг из `BACKLOG.md`.
10. Спот-чек карточки вуза: подписи лицензии и «иллюстративное фото» отрисованы.

## Не входит (YAGNI)

- Поиск фото общежитий — следующим шагом, вместе с разбором кейсов БОБРа.
- Срез 4 (стипендии/описания/требования) — отдельной спекой.
- Платный поисковый API (Exa) — владелец выбрал офсайт + Wikimedia; вернуться к вопросу
  можно после пилота, если покрытие окажется низким.
- Перегенерация или ретушь изображений — не фабрикуем.
- CDN и оптимизация раздачи картинок — вне достоверности.
