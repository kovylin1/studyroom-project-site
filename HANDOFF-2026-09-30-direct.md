## План следующей сессии

### Шаг 1. Нормализация названий (без сети)
В `scraper/lib/program-match.mjs` (общая для агрегаторов — прогнать её тесты
`node --test scraper/lib/program-match.test.mjs`):
- Hons ↔ Honours, «&» ↔ and, HR ↔ Human Resource, типографские апострофы;
- степень в начале и в конце («BSc X» ↔ «X BSc (Hons)», «Bachelor of Science in X»);
- хвосты «(Major)», «in Berlin», «(TR)/(EN)» и суффиксы языка.
Новые случаи — тестами. Цель: у Wollongong 0 «новых», у XJTLU только настоящие.

### Шаг 2. Проверка каждого вуза глазами (без сети, по выгрузкам)
Для каждого из 34: `node scraper/kompas-direct-fees.mjs --from-extracts --add-programs --slug=<slug>`
и отчёт `direct-fees-report-<slug>.json`. Чек-лист:
1. `sitePrograms` — правдоподобно для вуза? (сравнить с числом программ на сайте);
2. 5 случайных «новых» — открыть сайт, это настоящие программы с верным уровнем?
3. `cardProgramsNotOnSite` — что это: мусор, переименование или программа, которую парсер пропустил?
4. цены: 3 случайные — сумма и основа (год/курс) совпадают с сайтом? аудитория international?
5. `gaps` — нет ли среди пробелов того, что можно взять.
Вердикт по вузу: OK / подпилить парсер / GAP. Сводку — в `DIRECT-FEES-REVIEW.md`.
Чтобы не жечь деньги: одна сессия, без параллельных агентов (шесть агентов 29.09 стоили
большую часть $90), большие JSON — через node-однострочники, не читать целиком.

### Шаг 3. Встроить в путь агрегаторов
Сделать как у агрегаторов (`scraper/kompas-update.mjs`):
- запись `direct` в `AGGREGATORS` (или `--agg=direct[:slug]`): сбор = запускалка без `--apply`
  → рабочая копия с живого → применение в копию → **порог изменения** → перенос изменившихся
  карточек через гейт → `audit-catalog --gate` → отчёт в `site/public/api/update-runs.json`
  (его показывает панель менеджера, колонка «Прогон КОМПАСа»);
- метка источника у программ (`source: 'official'`, `kompasStatus: 'source-added'`) уже ставится;
- день в `scraper/sources/aggregator-schedules.json` (свободен 4-й) и строка в `scrape-staggered.yml`
  с Playwright. Черновик отдельного workflow `.github/workflows/scrape-direct.yml` лежит
  НЕЗАКОММИЧЕННЫМ в worktree — после решения владельца по деплою (ниже) либо удалить,
  либо переделать.

### Шаг 4. Применить и собрать
`--add-programs --apply` по вузам с вердиктом OK → `npm run build` в `site`
(после правки программ обязательно — гейт не ловит сироты `deadlines`) → коммит в PR #73.
