# Представление проекта — по полочкам

> Разбор от 2026-05-07. Это не повтор Site.md, а сборка проекта в одну картину перед тем, как лезть в код.
> Источник архитектуры: `sources/Site.md` (зеркало `inbox/Site.md`).

## 1. Суть в одну фразу

Машина, которая раз в месяц **сама собирает данные о заграничных универах**, **сама** их **раскладывает в одинаковую форму** и **сама публикует** лендинги на `studyroom.kz/{slug}`. Человек только подтверждает изменения.

## 2. Зачем (в чём боль)

- Универов — много (план — 100+). Вёрстка руками = месяцы и опечатки.
- Цены / дедлайны / программы меняются. Без автоматики лендинги быстро врут.
- API у универов и агрегаторов нет — только скрейпинг.
- Тильда / Webflow / WordPress не дают массово генерить страницы и не показывают, **что именно поменялось** для ревью.

## 3. Роли (кто что делает)

| Роль | Что делает |
|---|---|
| **ИИ-скрейпер** | Раз в месяц лезет на сайты, тащит данные, кладёт в JSON |
| **Claude** (внутри пайплайна) | Когда вёрстка нестандартная — извлекает данные из HTML/скриншота в схему |
| **Менеджер StudyRoom** | Видит PR с diff («цена 25k → 26k») в Decap UI, апрувит |
| **Cloudflare Pages** | Сама собирает Astro и раздаёт сайт миру |
| **Разработчик (ты + я)** | Поддерживает скрейперы, шаблон, схему |

## 4. Из чего состоит (5 блоков + cron + админка)

```
1. Скрейпер        → 2. Нормализатор    → 3. Хранилище данных
   (Playwright,       (Zod-схема           (data/universities/
    Cheerio,           University)           {slug}.json в git)
    Claude API)
                                              ↓
6. Месячный cron   ← 5. Хостинг          ← 4. Генератор лендингов
   (GitHub Actions    (Cloudflare Pages,    (Astro, [slug].astro,
    + diff + PR)       CDN, HTTPS)           один шаблон → N HTML)

         ↑
   7. Админка (Decap CMS на /admin) — поверх git, для менеджера
```

Эти блоки — **независимые слои**. Их можно делать по очереди и каждый видеть отдельно.

## 5. Как живёт один универ (от и до)

1. Cron просыпается раз в месяц.
2. Скрейпер заходит на `ox.ac.uk/admissions` (и/или агрегатор).
3. Парсит HTML; если вёрстка кривая — отдаёт Claude API → получает JSON по схеме `University`.
4. Сравнивает с прошлым `data/universities/oxford.json`.
5. Если разница — открывает PR с diff.
6. Менеджер открывает `/admin` (Decap), видит «Tuition: 25000 → 26000», жмёт Approve.
7. Merge → Cloudflare Pages пересобирает Astro → `studyroom.kz/oxford` обновлён за 30–60 сек.
8. Опционально — Claude кидает changelog в Telegram-бот StudyRoom.

## 8. Точки риска (где можно спотыкнуться)

1. **Нестабильная вёрстка источников.** Сайты универов любят менять разметку → скрейпер ломается. Лечится Claude-ом как fallback и алёрт-флагом «сегодня не получилось».
2. **Юридическая сторона скрейпинга.** Партнёрские сайты — ок (договор), агрегаторы — серая зона; ToS читать.
3. **Качество данных.** На сайтах часто противоречия (одна цена в одном месте, другая — в другом). Нужно правило «источник истины».
4. **Языки и валюты.** UK в GBP, US в USD, EU в EUR. Хранить «как есть», конвертировать на лету.
5. **Decap auth.** Decap хочет OAuth (GitHub/GitLab) — нужен публичный репо или прокси.
6. **Лимиты Claude API.** 100 универов × раз в месяц — терпимо, но если делать чаще — следить за расходом.
